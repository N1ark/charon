# Charon Lean

This folder implements a Lean 4 library for Charon, to deserialize and print the (U)LLBC ASTs
emitted with `--format postcard`.

- `Charon/Generated/Ast.lean`: the AST, generated from the Rust definitions by `make
  generate-asts`. It follows the Rust types closely (same names, strongly-typed ids,
  `IndexVec`/`IndexMap`s, ...). See `charon/src/bin/generate-asts/generate_lean.rs` for how we
  work around Lean's restrictions on (mutually) recursive types.
- `Charon/Generated/{Repr,BEq,Hashable}.lean`: the derived instances, in separate files because
  this is much faster to compile.
- `Charon/Generated/OfPostcard.lean`: the generated deserializers, on top of the postcard decoder in
  `Charon/Postcard.lean`.
- `Charon/Deserialize.lean`: the entry point, `CrateData.ofPostcardFile`.
- `Charon/Print.lean`: a pretty-printer, close to `charon pretty-print`.

The `charon-lean` executable can pretty-print a file, or run charon and pretty-print its output:
```
lake build
.lake/build/bin/charon-lean print foo.ullbc.postcard
CHARON_BIN=path/to/charon .lake/build/bin/charon-lean rustc -- foo.rs
```
When running charon, it extracts the ULLBC that is the closest to MIR (`--preset=raw-mir`) unless
another preset is passed; all the charon options are supported.

`make test` in the root of the repository runs the tests (`make charon-lean-tests` runs only the
Lean ones): like the charon-ml tests, they deserialize all the postcard files generated by the
charon test suite and check that our pretty-printer agrees with `charon pretty-print`. Known
differences are listed in `Test.lean`.

Note that building `Charon/Generated/Ast.lean` takes a few minutes and ~4.5GB of memory, because
Lean is slow to process the large nested mutual inductive types of the AST.
